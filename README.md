## 1. 에이전트 팀이란?

Claude Code에서 "여러 에이전트가 함께 일한다"는 개념은 크게 **두 층위**로 나뉩니다. 이 둘을 구분하는 것이 이해의 핵심입니다.

### 🧩 서브에이전트 (Subagent) — *하나의 세션 안에서*

**하나의 대화 세션 안**에서, 메인 에이전트가 특정 작업을 처리하도록 띄우는 보조 에이전트입니다.

- 각자 **독립된 컨텍스트 창**과 **전용 시스템 프롬프트**, **제한된 도구 접근 권한**을 가집니다.
- 중간 과정(도구 호출, 파일 내용)은 격리되고, **최종 요약 결과만** 부모 에이전트에게 돌아옵니다.
- 서로 **직접 대화하지 못하며**, 오직 부모에게만 보고합니다.
- 토큰 비용이 상대적으로 **낮습니다**(요약본만 전달).
- `Agent` 도구(구 `Task`)로 호출되며, 기본적으로 **백그라운드**로 실행됩니다.

### 👥 에이전트 팀 (Agent Team) — *여러 개의 독립 세션이*

**여러 개의 독립적인 Claude Code 세션**이 하나의 팀으로 묶여 협업하는 방식입니다.

- 한 세션이 **팀 리드(team lead)** 역할을 하고, 나머지는 **팀원(teammate)** 세션이 됩니다.
- 팀원끼리 **직접 메시지를 주고받을 수 있습니다**(리드를 거치지 않음) — `SendMessage` 도구 사용.
- **공유 작업 목록(shared task list)** 을 통해 스스로 일을 나눠 가집니다.
- 각 팀원이 **자기만의 전체 컨텍스트 창**을 갖기 때문에 토큰 비용이 **높습니다**.
- **실험적 기능**이라 별도 활성화가 필요합니다:

```json
// .claude/settings.json (또는 ~/.claude/settings.json)
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

### 📊 한눈에 비교

| 구분 | 서브에이전트 | 에이전트 팀 |
|---|---|---|
| 세션 수 | 1개 세션 | 여러 개의 독립 세션 |
| 병렬성 | 제한적(한 컨텍스트 내) | 완전 병렬(각자 별도 컨텍스트) |
| 통신 | 부모에게만 보고 | 팀원끼리 직접 메시지 |
| 조율 | 부모가 모두 관리 | 공유 작업 목록으로 자율 조율 |
| 토큰 비용 | 낮음(요약) | 높음(팀원마다 풀 컨텍스트) |
| 적합한 일 | 집중된 위임 작업 | 복잡한 협업 작업 |
| 설정 | 에이전트만 정의하면 됨 | 실험 플래그 활성화 필요 |

> 💡 **참고 — Agent View(`claude agents`)**: 여러 개의 백그라운드 세션을 한 화면에서 띄우고 상태(Working / Needs input / Completed / Failed)를 모니터링하는 대시보드입니다. "에이전트 팀"이 자동 협업이라면, Agent View는 내가 수동으로 여러 세션을 띄워 관리하는 관제탑에 가깝습니다.

## 2. 장점

| 장점 | 설명 |
|---|---|
| **컨텍스트 격리** | 각 에이전트가 자기 컨텍스트만 봄 → 관련 없는 내용으로 인한 오염(pollution) 방지 |
| **병렬 처리** | 여러 에이전트가 동시에 작업 → 전체 소요 시간이 *합*이 아니라 *가장 느린 하나* 기준 |
| **전문화(Specialization)** | 에이전트별로 다른 지침·도구·모델 지정 (예: 보안 리뷰어는 Opus/엄격, 성능 리뷰어는 Sonnet/속도) |
| **독립 검증** | 팀원이 서로의 결론을 반박·교차검증 → "경쟁 가설(competing hypotheses)"로 더 견고한 원인 분석 |
| **자율 조율** | 공유 작업 목록에서 팀원이 스스로 일을 claim, 리드는 고수준만 조율 |
| **파일 충돌 방지** | 각 에이전트를 별도 git worktree(`isolation: worktree`)에서 돌려 동시 수정 충돌 회피 |

**적합한 워크플로우 예시**
- **병렬 코드 리뷰**: 보안 / 성능 / 테스트 커버리지를 각기 다른 리뷰어가 동시에
- **경쟁 가설 디버깅**: 팀원마다 다른 원인 가설을 조사
- **신규 모듈 개발**: 팀원이 서로 다른 컴포넌트를 소유(파일 충돌 없음)
- **계층 횡단 변경**: 프론트엔드 / 백엔드 / DB 담당이 조율하며 진행

> ⚠️ **비용 주의**: 팀원 5명 = 약 5배 토큰 사용. 팀원들이 **독립적으로** 일할 수 있을 때 가장 효율적입니다.

## 3. 역할(에이전트) 정의 방법 — `.claude/agents/*.md`

에이전트(=역할)는 **Markdown 파일** 하나로 정의합니다. YAML 프론트매터(설정) + 본문(시스템 프롬프트) 구조입니다.

### 📁 파일 위치와 범위

| 위치 | 범위 | 우선순위 |
|---|---|---|
| `--agents` CLI 플래그 | 현재 세션만 | 높음 |
| `.claude/agents/` | 현재 프로젝트(팀 공유, git 커밋) | 중간 |
| `~/.claude/agents/` | 내 모든 프로젝트(개인용) | 낮음 |
| 플러그인 `agents/` | 플러그인 활성 범위 | 가장 낮음 |

> 두 디렉터리 모두 변경이 실시간 감지됩니다(재시작 불필요). 단, 세션 시작 시점에 `agents/` 폴더가 없었다면 재시작이 필요합니다.

### ⚙️ 프론트매터 필드

| 필드 | 필수 | 설명 |
|---|:---:|---|
| `name` | ✅ | 고유 식별자. 소문자·하이픈만. `@멘션`이나 `--agent`로 호출할 이름 |
| `description` | ✅ | **언제 이 에이전트에 위임할지** 설명. 구체적일수록 자동 위임 정확도↑ (예: "코드 변경 후 자동 실행") |
| `tools` | | 허용 도구(쉼표 구분). 생략 시 전체 상속. 예: `Read, Grep, Glob` |
| `disallowedTools` | | 차단할 도구 |
| `model` | | `sonnet` \| `opus` \| `haiku` \| `fable` \| 전체 모델 ID \| `inherit`(기본) |
| `permissionMode` | | `default` \| `acceptEdits` \| `plan` \| `dontAsk` 등 |
| `maxTurns` | | 최대 에이전트 턴 수 |
| `skills` | | 시작 시 미리 주입할 스킬 이름(쉼표 구분) |
| `memory` | | `user` \| `project` \| `local` — 세션 간 학습을 위한 영속 메모리 범위 |
| `effort` | | 추론 강도: `low` \| `medium` \| `high` \| `xhigh` \| `max` |
| `isolation` | | `worktree` 지정 시 임시 git worktree에서 실행 |
| `color` | | 작업 목록 표시 색 (`red`, `blue`, `green` …) |

### 📝 예시 에이전트 정의 파일

```markdown
<!-- .claude/agents/security-auditor.md -->
---
name: security-auditor
description: 보안 취약점 감사 전문가. 인증·인젝션·데이터 보호 이슈를 찾을 때 사용.
tools: Read, Grep, Glob, Bash
model: opus
effort: high
isolation: worktree
---

당신은 OWASP Top 10, 암호화, 인증, API 보안에 정통한 시니어 보안 감사관입니다.

감사 절차:
1. 자격증명 저장·DB 쿼리·API 엔드포인트를 검색한다
2. SQL 인젝션, XSS, CSRF, 인증 우회 벡터를 점검한다
3. 암호화/해싱 구현을 검토한다
4. 심각도 등급과 함께 우선순위화된 발견 목록을 제공한다

각 발견마다: 취약점 설명 → 취약 코드 → 안전한 코드 예시 → 관련 표준 링크.
심각/높음 이슈를 먼저, 오탐은 피할 것.
```

## 4. 세션 생성 & 역할 지정

### 🚀 에이전트 호출 3가지 방법

**① 자연어(자동 위임)** — Claude가 `description`을 보고 알아서 위임
```
이 PR을 보안 관점에서 리뷰해줘
```

**② `@멘션`(강제 호출)** — 특정 에이전트를 반드시 실행
```
@security-auditor 인증 모듈 좀 봐줘
```

**③ 세션 전체를 특정 역할로 실행** — CLI 플래그 또는 설정
```bash
claude --agent security-auditor
```
```json
// .claude/settings.json — 기본 역할로 고정
{ "agent": "security-auditor" }
```

### 🏗️ 내장 에이전트 타입

| 에이전트 | 도구 | 용도 |
|---|---|---|
| **Explore** | 읽기 전용 | 빠른 코드베이스 탐색·검색 |
| **Plan** | 읽기 전용 | 계획 모드용 리서치 |
| **general-purpose** | 전체 | 탐색+실행이 필요한 복잡한 다단계 작업 |
| **claude** | 전체 | 폴백(catch-all), 백그라운드 세션 기본값 |

> 같은 이름의 커스텀 에이전트를 만들면 내장 에이전트를 덮어쓸 수 있습니다.

### 🔗 결과가 돌아오는 방식

- **동기(foreground) 서브에이전트**: 같은 턴에서 즉시 결과 반환 (`run_in_background: false`)
- **백그라운드 서브에이전트**(기본): 나중 턴에 완료 알림으로 도착, 그동안 메인은 계속 진행
- **에이전트 팀**: 팀원끼리 `SendMessage`로 직접 소통, 리드가 고수준 조율

## 5. 실전 예시: RFP 대시보드 작업으로 보는 흐름

> 이번 대화(`RFP_checklist.xlsx` 대시보드 자동화)를 예시로, **단일 에이전트가 한 일 → 선택 지점 → 팀으로 확장 시**를 순서대로 봅니다.

### 5-1. 실제로는 "단일 에이전트" 세션이었습니다

이번 작업은 사실 **에이전트 팀이 아니라 에이전트 1명(Claude)** 이 처리했습니다. 진행 흐름:

```
사용자 요청: "대시보드 시트에 RFP 판정 통계를 만들어줘"
      │
      ▼
[에이전트: Claude]  ── Skill(xlsx) 로드
      │  ├─ 환경 조사: Python/Node/LibreOffice 없음 → Excel COM(PowerShell) 채택
      │  ├─ 원본 시트 구조 분석(전체 체크리스트 / SFR-001~008)
      │  ├─ COUNTIF/COUNTIFS 수식으로 ①~④ 표 생성
      │  └─ 값 검증 후 원본 반영
      ▼
결과: 대시보드 4개 통계표 완성(①RFP판정 ②항목별 ③판정 ④판정CMS)
```

이 작업 중 **탐색이 무거웠다면** `Explore` 서브에이전트에게 "이 워크북의 모든 시트 구조를 조사해줘"라고 위임할 수도 있었습니다. 즉, *단일 세션 안에서 서브에이전트로 확장*이 가능한 지점이었죠.

### 5-2. 진행 중 제가 제시한 선택지 & 사용자가 고른 항목 ✅

작업 도중 실제로 사용자에게 제시했던 **결정 지점**과 선택 결과입니다.

**🔸 선택 지점 A — 파일 반영 방식** (원본이 Excel에서 열려 있어 덮어쓰기 실패했을 때)

- [ ] **옵션 1** — 완성본을 별도 파일(`RFP_checklist_대시보드완성본.xlsx`)로 두고 그대로 사용
- [x] **옵션 2** — 원본 이름 유지: Excel을 닫은 뒤 원본에 덮어쓰기 → **사용자 선택** ("반영해줘")

**🔸 선택 지점 B — ③ 판정 통계가 갱신되지 않는 문제 해결**

- [x] ③ 판정 결과별 개수의 참조 대상을 **전체 체크리스트 J열 → 각 SFR 시트 판정(H)열**로 변경 → **사용자 요청대로 반영**

**🔸 선택 지점 C — ④ 판정(CMS)에 항목 추가**

- [x] `N/C (Not CMS)` 항목을 N/A 아래에 추가하고 미검증·합계를 자동 재계산 → **사용자 요청대로 반영**

> 이처럼 Claude Code에서는 되돌리기 어렵거나 외부에 영향을 주는 작업(파일 덮어쓰기 등) 앞에서 **선택지를 제시하고 사용자 승인을 기다립니다.**

### 5-3. 만약 이 작업을 "에이전트 팀"으로 했다면?

같은 RFP 검증 작업을 규모가 큰 팀 작업으로 확장한다고 가정하면, 다음처럼 **역할을 나눈 팀**을 구성할 수 있습니다.

```
          [팀 리드: Claude — 조율/취합]
                     │  공유 작업 목록
        ┌────────────┼────────────┐
        ▼            ▼            ▼
 [rfp-analyzer] [dashboard-builder] [qa-verifier]
  원본 시트 분석   COUNTIF 표 생성      값 교차검증
  판정값 집계       서식·레이아웃        합계 133 일치 확인
```

각 역할을 `.claude/agents/`에 정의합니다:

```markdown
<!-- .claude/agents/dashboard-builder.md -->
---
name: dashboard-builder
description: 엑셀 대시보드 시트에 COUNTIF/COUNTIFS 집계표를 수식으로 생성. 원본 데이터는 수정하지 않음.
tools: Read, Bash
model: sonnet
---
당신은 엑셀 자동화 전문가입니다. 하드코딩 대신 항상 수식을 사용하고,
기존 시트의 서식·데이터를 보존하며 지정된 대시보드 시트에만 작성합니다.
작업 후 반드시 값을 재계산해 합계가 원본과 일치하는지 검증합니다.
```

```markdown
<!-- .claude/agents/qa-verifier.md -->
---
name: qa-verifier
description: 집계 결과를 원본과 교차검증. 합계·항목별 개수 불일치를 찾아 보고.
tools: Read, Bash
model: opus
effort: high

당신은 검증 담당입니다. 대시보드의 모든 표를 원본 데이터와 대조해
```

## 부록 A. 실제 자연어 대화 전문 (생성 예제)

> 이 부록은 위 대시보드가 **어떤 자연어 대화를 통해 생성되었는지** 그대로 재현한 것입니다.
> 에이전트에게 명령을 내리고, 에이전트가 선택지를 제시하고, 사용자가 고르는 **실제 상호작용 패턴**을 보여주는 것이 목적입니다.

**표기 규칙**
- 👤 = 사용자가 자연어로 입력한 실제 요청
- 🤖 = 에이전트(Claude)의 응답 요약
- 체크박스 = 에이전트가 **제시한 선택지 전체**를 나열하고, `[x]` 로 **사용자가 고른 항목**을 표시
  - `[x]` = 사용자가 선택/요청함
  - `[ ]` = 제시했으나 선택되지 않음(열린 제안 포함)

### 🗣️ 턴 1 — 대시보드 최초 생성

👤 **사용자**
> RFP_checklist 이 엑셀에 보면 대시보드 시트가 있는데 여기에 다른시트에 있는 RFP 판정 개수와 항목별 개수 판정 결과별 개수 통계를 확인할 수 있도록 수정해줘

🤖 **에이전트**
- 환경 조사: Python·Node·LibreOffice 없음 → **Excel COM(PowerShell)** 방식 채택(자체 판단, 별도 선택지 제시 안 함)
- 원본 구조 분석 후 `COUNTIF`/`COUNTIFS` 수식으로 표 3개 생성: ① RFP 판정 개수 ② 항목별(SFR) 개수 ③ 판정 결과별 개수
- 값 검증(합계 133 일치) 후 원본 반영 완료
- 마무리로 **열린 제안** 제시:

**🔹 제시된 후속 선택지 (열린 제안)**
- [ ] 표 배치를 가로 배열로 변경
- [ ] 차트 추가

> ↳ 사용자는 둘 다 고르지 않고 다음 요청으로 진행.

---

### 🗣️ 턴 2 — ④ 판정(CMS) 통계 추가 & 파일 반영 방식 선택

👤 **사용자**
> ③ 판정 결과별 개수 아래에 판정(CMS) 통계를 따로 만들어주라 각 시트에 헤더 항목 추가해 놨어

🤖 **에이전트**
- 각 `SFR-001~008` 시트의 새 열 **판정(CMS) = I열** 발견 → 8개 시트 전체를 집계하는 ④ 표 생성
- 원본 반영 시도 → **파일이 Excel에서 열려 있어 덮어쓰기 실패(busy)**
- 완성본을 별도 파일로 백업한 뒤 **명시적 선택지 2개 제시**:

**🔹 결정 지점 A — 파일 반영 방식 (둘 중 택1)**
- [ ] **옵션 1** — 완성본을 별도 파일(`RFP_checklist_대시보드완성본.xlsx`)로 그대로 사용
- [x] **옵션 2** — 원본 이름 유지: Excel을 닫은 뒤 원본에 덮어쓰기 ← **다음 턴에서 사용자가 선택**

🤖 **에이전트**

### 🗣️ 턴 4 — ③이 갱신되지 않는 문제 진단·수정

👤 **사용자**
> ④ 판정(CMS) 결과별 개수는 반영이 되는데 ③ 판정 결과별 개수는 반영이 안되네

🤖 **에이전트**
- 원인 진단: ③이 **전체 체크리스트 J열**(사용자 편집과 비연동, 빈 값)을 참조하고 있었음
- ④는 SFR 시트를 직접 참조해 정상 갱신되던 것과 대비
- **단일 해결책을 제시·적용**(다중 선택지 없음):

**🔹 결정 지점 B — ③의 참조 대상 변경**
- [x] ③ 판정 결과별 개수의 참조를 **전체 체크리스트 J열 → 각 SFR 시트 판정(H열)** 로 변경 ← **적용됨**

- 수정·검증 후 반영 시도 → 다시 busy → "Excel에서 파일을 닫아주세요" 안내

### 🗣️ 턴 6 — ④에 N/C 항목 추가

👤 **사용자**
> ④ 판정(CMS) 결과별 개수는 N/C (NOT CMS) 라는 항목을 추가해줘

**🔹 결정 지점 C — ④ 항목 추가**
- [x] `N/C (Not CMS)` 항목을 N/A 아래에 추가하고 미검증·합계 자동 재계산 ← **적용됨**

### 📌 이 예제가 보여주는 "생성 패턴"

| 단계 | 자연어 트리거 | 에이전트의 반응 유형 |
|---|---|---|
| 최초 생성 | "…통계를 확인할 수 있도록 수정해줘" | 자체 판단으로 실행 + 열린 제안 |
| 기능 추가 | "…판정(CMS) 통계를 따로 만들어주라" | 실행 → 막힘 → **선택지 제시** |
| 승인 | "반영해줘" | 선택 확정 후 실행 |
| 버그 지적 | "…③은 반영이 안되네" | 원인 진단 → 단일 해결책 적용 |
| 세부 조정 | "N/C 항목을 추가해줘" | 구조 재구성 + 자동 재계산 |

> 핵심: 에이전트는 **되돌리기 어려운 작업(파일 덮어쓰기)** 앞에서 선택지를 제시하고, 사용자의 "반영해줘" 같은 **명시적 승인**을 기다린 뒤 실행합니다. 이 승인 지점이 곧 위 체크박스로 표시된 "선택 항목"입니다.
