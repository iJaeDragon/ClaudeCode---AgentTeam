# 📡 팀 통신 규약 (Protocol)

모든 팀원(리더 포함)이 공유하는 규칙. 세션 간 유일한 통신 수단은 두 가지다.

1. **직접 메시지** — `mcp__ccd_session_mgmt__send_message(session_id, message)`
   - 상대 세션에 "From {내 세션 제목}" 사용자 턴으로 도착한다.
   - 즉시 알림·질의·응답·핸드오프에 사용.
2. **공유 파일** — 같은 작업 폴더의 `team/보드.md`, `team/로스터.md`
   - 지속 상태(작업 목록, 인터페이스 계약, 검토 의견)의 **진실의 원천**.
   - 메시지는 "봐달라"는 알림, 실제 내용은 파일에 쓴다.

## 세션 식별 (중요)
- 각 세션은 **자기 sessionId를 모른다.** 대신 `list_sessions`로 **다른** 세션들을 본다.
- 그래서 식별은 **세션 제목**으로 한다. 팀원 탭 이름을 `리더`/`개발자`/`RFP검증`/`코드분석`으로 맞춘다.
- 리더가 `list_sessions` 결과에서 제목으로 각자를 찾아 `로스터.md`에 `역할 → sessionId`를 확정 기록한다.
- 이후 누구든 상대에게 보내려면 `로스터.md`에서 sessionId를 조회해 `send_message`.

## 부팅 시퀀스
1. **팀원**: 자기 브리핑 파일을 읽는다 → 역할 확정.
2. **팀원**: `list_sessions`로 리더(제목 `리더`)를 찾는다 → `send_message`로 "✅ {역할} 준비 완료. 대기 중." 보고.
   - 리더를 못 찾으면 `로스터.md`에 "{역할} 준비 완료 (리더 대기)"만 남기고 대기.
3. **리더**: `list_sessions`로 팀원 3명을 수집 → `로스터.md`에 sessionId 확정 → 각자에게 작업 배정/지시.

## 협업 흐름 (표준 사이클)
1. **리더** 목표 수신 → 작업으로 분해해 `보드.md`에 항목 추가.
2. **RFP검증자**가 해당 작업의 요구사항을 `RFP`에서 확인 → 요건·수용기준을 `보드.md`에 정리하고 개발자에게 전달.
3. **개발자**가 요건대로 구현 → 보드 상태 `진행→검토`로 갱신하고 RFP검증자·리더에게 검토요청.
4. **RFP검증자**가 요구사항 충족 여부 검토 → 통과/보완 의견을 `보드.md`에 기록.
5. **코드 분석자**가 변경분을 분석해 리포트 2종 생성(아래) → 리더에게 보고.
6. **리더**가 통합·확정하고 다음 작업 배정.

## 작업 규칙
- **작업 배정**: 리더만 새 작업을 만들고 담당을 지정한다.
- **진행 보고**: 담당자는 상태가 바뀔 때마다 `보드.md` 상태 갱신(`대기→진행→검토→완료`, 막히면 `막힘`).
- **팀원 간 직접 협업**: 리더를 거치지 않아도 된다(예: 개발자가 RFP검증자에게 요건 질의). 단 결정·의견은 `보드.md`에 기록.
- **한 파일 동시수정 금지**: 같은 소스 파일을 두 세션이 동시에 수정하지 않는다. 공유 파일 수정 전엔 최신본을 다시 읽는다.
- **충돌/결정**: 리더가 중재·확정한다.

## 메시지 포맷 (권장)
```
[역할→역할] 유형: 한 줄 요지
본문 / 참조: 보드.md #항목번호
```
유형 예: `보고` `질의` `응답` `배정` `요건전달` `검토요청` `검토결과` `분석완료` `막힘`

## 종료
작업이 끝나면 리더가 `보드.md`에 최종 요약을 쓰고 각 팀원에게 "해산" 메시지를 보낸다.
